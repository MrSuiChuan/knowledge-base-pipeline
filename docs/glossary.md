# 术语表

只解释**本仓库有特定含义**的词。通用词不在这里凑数。

| 术语 | 含义 | 别混淆 |
| --- | --- | --- |
| **六类知识** | 每张表要采集的六类事实：BASIC_INFO（身份）/ COLUMN_BASIC_INFO（字段语义）/ DDL_SQL（结构约束）/ SCHEDULE_TASK（产出节奏）/ QUALITY_RULE（质量约束）/ PARTITION_INFO（切分方式） | 不是"六张文档"，是六类**事实**，落在同一份快照的每一行里 |
| **快照（snapshot）** | 某个时间点从某个来源采到的六类事实，落在 `.kb/runtime/snapshots/metadata-snapshot-*.json` | 它不是知识库成品；成品在 `.kb/repo/` |
| **知识源** | 一次采集依据的外部系统：`mock` / `platform-mcp` / `oss:<组件id>` | 与"知识库"不是一回事：来源是输入，知识库是产物 |
| **采集器** | 把某个组件的元数据翻译成六类契约的那段代码，按组件登记在 `engine/sources/registry.json` | 与"执行器"不同：执行器是跑 SQL/作业的地方（本仓库没有执行器） |
| **组件注册表** | `engine/sources/registry.json`：支持哪些组件、怎么连、能采到哪几类、验证到哪一层 | 连接信息不在这里，在项目级 `.kb/config.json` 的 `sources.<组件id>` |
| **NOT_APPLICABLE** | 这个组件**压根没有**这一类知识（附理由），例如消息组件没有字段 schema | 不是"没采到"——那是 `COLLECT_FAILED`（附原始错误）。两者混起来就等于编 |
| **口径** | 一个概念在业务上的确定定义（例："活跃"= 当日有任意行为） | 不是"字段注释"；口径冲突是质检要拦的第一类问题 |
| **六层链接（v41）** | 质检检查的六层引用完整性：L1 域索引→导航 / L2 锚点→表文档 / L3 目标→表文档 / L4 上游→表文档 / L5 JOIN→表文档 / L6 SLA 规则→rules | 不是"超链接检查"，是**知识树的引用完整性** |
| **机器资产** | `.kb/` 下由引擎写、不允许手工改的东西：`_state.json`、`runtime/**`、`.kb-audit-*.json`、`.kb-manifest.json` | 改了会被 hook 拦；手改等于伪造留证 |
| **留证** | 产物里可复核的原始依据：审计文件的 `content_hash`、快照文件、发布清单 | 不是"日志"：留证要能被门消费，只写不读的不算 |
| **硬门 / 出口门** | 阶段出口上"只认机器证据"的检查；不过就不许前进 | 与"提示"不同：提示是自然语言，硬门是返回码与 gate 键 |
| **提案（proposal）** | 沉淀质量规则的唯一入口：propose → 引擎五检 → Owner approve → `active` | 直接改 `rules/**` 会被 hook 拦（`rules_direct_write_guard`） |
| **反哺（refresh）** | 拿新快照与旧快照比，把变化回灌到文档的自动章节，产出 drift 报告 | 只回灌"元数据能确定"的部分（身份/字段语义），业务语境与 FAQ 靠人 |
| **易变字段** | 统计类字段（如 `row_count`），会在快照之间无意义抖动，**不参与**漂移判定 | 不参与判定 ≠ 不展示：文档里照常显示行数 |

## 常见误解

- **"装了插件就等于有了知识库"**：不是。插件是工艺与门控；知识库要在你的项目里
  `/kb-setup` → 采集 → 生成 → 质检 → 发布 才长出来。
- **"hook 是安全边界"**：不是。它让偷懒变贵，真正拦事的是引擎内的门与留证比对；
  把写操作藏进脚本文件再执行，hook 看不见（见 SECURITY 的 Known limits）。
- **"审计过了就能发布"**：还要 Owner 终签。APPLIED（机器门禁通过）与 REVIEWED（人签）是两个时间轴。
- **"NOT_APPLICABLE 是没采到"**：不是，是这类知识在该组件里不存在；采失败会另记 `COLLECT_FAILED`。
